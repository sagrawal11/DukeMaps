| Graph model of the map | | | |
| Dijkstra | **Not publicly documented for Maps.** Google publishes Maps *outputs* and the ML behind ETAs, but not the core shortest-path algorithm behind directions. Dijkstra itself is classical: Dijkstra 1959, "A note on two problems in connexion with graphs," _Numer. Math._ 1:269–271. | Dijkstra with a priority queue (binary/Fibonacci heap) is the universal baseline every production router is built on or benchmarked against. Authoritative public survey: Bast, Delling, Goldberg, Müller-Hannemann, Pajor, Sanders, Wagner & Werneck 2016, "Route Planning in Transportation Networks" (arXiv:1504.05140). | Binary min-heap Dijkstra with decrease-key (`src/algorithms/heap.ts`, `dijkstra.ts`). Time-dependent: each edge is priced at `dist[u]` — the walker's arrival time at its tail — which stays optimal because the crowding model is FIFO (derivation in `src/graph/time.ts`). The optimum baseline the equal-cost test holds the other optimal searches to. On the far-corner pair it settles the whole 6,189-node graph (Dijkstra's worst case). |
| A\* (straight-line heuristic) | **Not publicly documented for Maps.** A\* is classical: Hart, Nilsson & Raphael 1968, "A Formal Basis for the Heuristic Determination of Minimum Cost Paths," _IEEE Trans. Syst. Sci. Cybern._ 4(2):100–107. | A\* with an admissible heuristic is standard for geographic routing — a Euclidean/great-circle lower bound, or tighter landmark (ALT) bounds from the triangle inequality: Goldberg & Harrelson 2005, "Computing the Shortest Path: A\* Search Meets Graph Theory." Open routers (e.g. Valhalla) use bidirectional A\*. (Bast et al. 2016 survey.) | A\* with heuristic = great-circle distance ÷ `WALK_SPEED_MPS` (`src/algorithms/astar.ts`). Admissible **and** consistent — proof in the file header: `h(u) − h(v) ≤ straight-line(u,v)/v_max ≤ cost(u,v)`, so no node is ever reopened and it returns Dijkstra's exact cost. Settles 0.73× Dijkstra's nodes on the far pair. The ÷speed only converts the straight-line *distance* into seconds so the estimate is comparable to time-valued edge costs; time stays the cost, so crowding still shapes the route. |
| Bidirectional search | **Not publicly documented for Maps.** Classical: Pohl 1971, "Bi-directional Search," _Machine Intelligence_ 6; correct bidirectional A\* via potentials: Goldberg & Harrelson 2005. | Grow a forward frontier from the source and a backward one from the target, stop once they provably can't beat the best meeting — the standard ~2× pruning and the substrate most speedup techniques (incl. contraction hierarchies) build on (Bast et al. 2016). The naive forward-to-target / backward-to-source A\* is wrong; it needs **balanced/consistent** potentials. | `src/algorithms/bidirectional.ts`: biDijkstra (zero potentials) + biA\* with balanced potentials `pF = (h_t − h_s)/2`, `pB = −pF`, so `pF + pB = 0` everywhere and the clean stop `min keyF + min keyB ≥ μ` is valid for both. biA\* settles the fewest nodes of all six (0.54× Dijkstra). Recorded honestly: bidirectional prices edges at the **departure-time snapshot** (static metric) — it can't know the walker's mid-path arrival time — so true time-dependent routing stays with the unidirectional search, or CCH in Phase 5c. |
| Contraction hierarchies | | | |
| Spatial index (quadtree / R-tree) | **S2 Geometry** — Google's open-source spherical spatial index: the sphere is cut into a hierarchy of cells numbered along a Hilbert curve, giving fast region covering + point lookup (s2geometry.io, github.com/google/s2geometry). Published as a general spatial library, _not_ specifically documented as Google's routing snap/map-matching index. | Quadtrees, k-d trees, R-trees, and geohash/uniform grids for nearest-neighbour and map-matching/snapping (classical: Finkel & Bentley 1974, quadtrees; Guttman 1984, R-trees). | A region **quadtree** over node/edge bounding boxes with branch-and-bound nearest-neighbour in a local equirectangular (meters) frame (`src/spatial/`). Chosen over an R-tree because the data is static and near-uniform — no incremental inserts/rebalancing to pay for — and it's simpler to explain on paper. Serves nearest-node + snap-to-edge; ~4× / ~11× vs a linear scan (`notes/measurements.md`). |
| Time-dependent weights | Predictive + live **traffic** for *driving* ETAs (ML/graph nets). Google does **not** publicly document pedestrian class-change crowding. Source: DeepMind, "Traffic prediction with advanced Graph Neural Networks" (2020) — _confirm exact URL_. | Time-dependent shortest paths on **FIFO** networks: Dijkstra/A\* stay optimal iff the network is no-overtaking (classical: Dreyfus 1969; Orda & Rom 1990). | A crowding multiplier near academic buildings that peaks just after class-end times, plus `hours` gating, evaluated at **arrival** time. FIFO is preserved because the bump's decay slope stays above −1/base for short campus edges (derivation in `src/graph/time.ts`). |
